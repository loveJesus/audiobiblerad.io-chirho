# Prepare the first native release package

The owner asks to finish the mobile apps for initial store versions. This unit prepares the Android release bundle locally, before signing, key creation or store actions. Keep the current compiled source, application ID and version unchanged. The existing isolated build entry owns cache selection, resource preparation and task execution; do not add a second wrapper. Claude owns the package run and inventories; root owns the compiler slot, ledger, review and landing. The compiler slot and Apple candidate runtime are serialized; this build runs while the Apple instrument is prepared as files only.

- [x] Reconcile the current APK/runtime result, existing build entry and unsigned release task without changing source or signing.
- [x] Run the purchased-set bundleRelease task when the compiler slot is free, preserving any failed output.
- [x] Inspect the resulting bundle for release identity, non-debuggable behavior, unsigned status, permissions and exact public metadata/effect assets; retain the unique package privately with its hash.
- [x] Record release-variant, API 37, physical-device and store gates separately; do not treat a local AAB as an upload or approval.
- [x] Review and land the bounded package receipt and release handoff without creating a key, console record or submission.

The existing developer account's store identity, legal answers and contact information remain separate from package compilation. API 37 background audio still requires runtime acceptance. [Google's dedicated background-audio guidance](https://developer.android.com/about/versions/17/changes/bg-audio) names MediaSessionService and explicit notification/media-key interactions as supported lifecycle paths, so no speculative target downgrade is part of this unit.
